# Contributing

Thanks for helping make this problem-solving journal more useful. Contributions of every size are welcome, including a clearer explanation, a carefully chosen edge case, a bug report, or an alternative Python solution.

## What you can contribute

- An alternative solution or a meaningful improvement to an existing one.
- Examples, hints, constraints, or explanations that are clearer or more accurate.
- Useful edge cases and tests.
- A new challenge proposal.
- A correction to behavior or complexity analysis.

## Keep the original solution safe

Do not overwrite a day's original solution when adding another approach. Add an alternative implementation under that day's `solutions/` directory, for example:

```text
Day6/solutions/two_sum_hash_map.py
```

Use a descriptive filename rather than a personal username so the approach is easy to find. Add a short comment or a neighboring README naming the contributor and explaining the approach. For a documentation-only improvement, edit the relevant daily README directly.

For a new day, follow the existing `DayN/` pattern: include a problem-first `README.md` and the original solution file. Keep examples and stated requirements supported by the challenge proposal.

## Pull request process

1. Fork the repository.
2. Create a feature branch for your change.
3. Add or improve a solution, problem guide, example, or documentation.
4. Run the affected Python file or otherwise check your changes, and describe what you checked. For explanation-only changes, review the Markdown and links.
5. Open a pull request with a clear summary and any relevant issue number.

## What to include

For code contributions, explain the approach and include time and space complexity when applicable. Mention notable edge cases. Keep dependencies out unless they are necessary and approved for the project. For a new or revised problem, distinguish confirmed requirements from assumptions and provide representative inputs and outputs.

Please be welcoming in reviews. The purpose is to learn together, and a different correct approach is a useful contribution.
